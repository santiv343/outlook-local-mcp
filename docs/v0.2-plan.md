# v0.2 implementation contract

The published v0.1.0 remains available. This change adds the authorized journey:
find a message with richer filters, read its conversation, open it in Outlook,
prepare a draft/reply, review a send preview, and optionally submit that draft.
All public artifacts stay English; no personal or mailbox data enters the repository.

This is one package with one implementation owner. Reuse the existing COM worker,
supervisor, strict models, cursor store, error mapping and MCP transport. No new
service, database, agent framework, transport or dependency is needed.

## Required behavior

R1. Default startup exposes read-only tools only. `--enable-write-tools` additionally
exposes `open_email`, `create_draft`, `reply_to_email`. `--enable-send` requires that
flag and additionally exposes `prepare_send` and `send_draft`. The worker enforces
the same capability selection as the public tool list. Configuration generation
preserves the selected flags. Mutation annotations are not read-only or idempotent.

R2. `open_email(entry_id, store_id)` validates a mail item, displays its nonmodal
Outlook window and activates it. Return identifiers and `opened: true`. Opening
can change Outlook's read state according to its settings; document this explicitly.
Never execute HTML ourselves or start a login/profile dialog.

R3. `create_draft(to, subject, body, cc=[], bcc=[], store_id?, account_email?)` creates and saves a
plain-text draft in the selected/default account's Drafts folder. Validate explicit
SMTP addresses before COM; resolve recipients before saving. Select the sending
account by its delivery-store ID, never by display name or the first arbitrary
account. An explicit account SMTP address must identify exactly one live account;
without store_id, derive its delivery store. If both selectors are present they
must agree. Without account_email require exactly one matching account; reject
zero/ambiguous matches. Reject accounts without a delivery store. Return draft IDs, actual
sender account, resolved recipients, subject and body. No send occurs. Draft input
limits: 100 recipients, 998 subject characters, 30,000 body characters.

R4. `reply_to_email(entry_id, store_id, body, reply_all=false, account_email?)` creates a native
reply or reply-all draft, using Outlook's recipient/thread relationships, prepends
the provided text to the quoted reply as plain text and saves. Here store_id locates
the original, which may be in an archive/shared store; it does not select the
sending store. Preserve and validate the native reply account unless explicitly
overridden by a uniquely matched account_email. Verify the resulting saved draft
belongs to that account's Drafts folder. Return the same
reviewable draft result, including the actual sender and recipients. It never sends
or changes the original message. Preserve the complete quotation even when the
result exceeds the input-body limit; paginate the returned draft body using existing
body fields without silently shortening the saved content. The caller uses
`open_email` to review in Outlook.

R5. `read_conversation(entry_id, store_id, limit=10, cursor?, body_limit=2000)` reads
the native Conversation table, including visible items across stores/folders,
in native ConversationIndex order. Use the existing bounded cursor/coverage engine;
at most 20 messages per page and 30,000 body characters per message. Each mail has
the usual paged body metadata; use `read_email` to continue a truncated body.
No conversation or a disabled/unsupported conversation store produces an explicit
error, not an invented subject-based thread. Deleted Items are excluded by Outlook's
Conversation table and must be documented. Non-mail and inaccessible items use the
existing omission policy; deduplication keys include both store and message IDs.
Add PR_STORE_ENTRYID to the table and use Row.BinaryToString for each row's store;
never substitute the anchor store. Each message reports its own folder/store IDs.
Page-level location identifies only the anchor. Bind cursor state to anchor IDs
and body_limit; only limit may change.

R6. `search_emails` additionally accepts `recipient`, `category`, `importance`
(`low`, `normal`, `high`) and `attachment_name`. Text filters are case-insensitive
literal substrings; category is an exact category-name match, split using the
Windows regional list separator. All filters combine with AND. Read recipient or
attachment properties only when their filter is requested. Bound metadata traversal
using existing limits. Missing metadata makes an unmatched predicate inconclusive,
with omission/coverage reporting rather than false absence. Summaries expose available
conversation ID, category names and importance without changing existing fields.

R7. Sending is a two-call, optional capability. `prepare_send(entry_id, store_id, account_email)`
requires a saved, unsent plain-text draft in its account's Drafts folder, resolved
SMTP recipients and an explicitly selected, uniquely matched live account. The
selected account must own the draft's actual Drafts store/folder; a conflicting
non-null native SendUsingAccount is rejected. Outlook can lose its transient account
reference after releasing/re-fetching a saved draft, as observed in the real probe.
The preview selects the account for the approved MCP send, not for a later manual send.
Resolve any represented
From identity and require its SMTP address to match the account; reject delegated
or unresolvable overrides. A nonempty SentOnBehalfOfName display name alone does not
prove delegation; use the represented SMTP identity where available. Programmatic sending
initially supports drafts without attachments; existing HTML/attached drafts can
be opened and sent through Outlook's own UI. This keeps the reviewed content exact
without downloading files or claiming plain text reviews HTML/attachment payloads.
Return sender, recipients, subject, full body up to 30,000 characters, digest,
draft_modified_at, one-use confirmation token and a five-minute expiry. A larger body needs review
and sending in Outlook. No truncation in a send preview.

`send_draft(entry_id, store_id, confirmation_token)` revalidates and hashes the current
full sender/recipient/subject/body data before invoking Send. A changed draft, expired
token, different IDs or reused token is rejected. Consume the token before Send.
Hash the same canonical preview returned to the client: account and resolved From
identity, each SMTP recipient including its To/Cc/Bcc role, subject and complete body.
Recheck saved/unsent status, actual Drafts location, account, format, recipient
resolution and absence of attachments immediately before sending. A new preview
replaces any earlier preview for that draft; a send attempt consumes every preview
for that draft. Keep at most twenty previews, storing only IDs, selected account SMTP,
digest and expiry, never body copies. Include LastModificationTime in the canonical
preview as supplemental evidence of saved edits, not a unique version identifier.
Immediately before Send, explicitly assign the bound account using COM PUTREF with
the member resolved by name. Consume tokens and mark mutation_attempted before PUTREF.
Verify the actual assigned account and unchanged sender, recipient roles, subject,
body, format, attachment absence and draft location after assignment. Do not require
Saved=true after our own assignment, which can dirty the item, and never Save between
PUTREF and Send. Verify Saved=true and the complete preview before assignment.
Client descriptions require explicit user approval of the preview before sending.
The token proves revision continuity, not human identity or client authorization;
the enabling user/client remains the authority. Concurrent edits are best effort
because Outlook offers no transaction combining comparison and Send.

Success means `submitted_to_outlook`, not delivered. Once the parent dispatches a
mutating request, timeout/disconnect/cancellation is conservatively
WRITE_OUTCOME_UNKNOWN with retryable=false; it does not infer whether COM reached
Save/Display/Send. Pre-dispatch failures retain normal error semantics. The worker's
local mutation-attempt boundary covers the first mutation through response construction
and serialization. Post-mutation output failures at the MCP boundary also preserve
unknown-outcome semantics. No stage IPC or automatic retry is added. Tell the caller
to inspect Outlook/Drafts/Outbox/Sent Items.
For send failures, the token stays consumed. Worker restart clears previews/cursors.
The supervisor never kills Outlook. There are no delete/move/mark-read tools.

## Sequence and acceptance

### Represented From correction after repeated review failure

Candidate `82e61f8` closed three initial findings, but its general `ITEM_NOT_FOUND`
category also accepted invalid EntryIDs and file-not-found errors as property absence.
This repeated the inaccessible-From failure class; implementation paused to revisit
the producing boundary. Generic locator errors cannot authorize identity fallback.

1. Narrow only the represented SMTP read boundary. Reuse numeric HRESULT/EXCEPINFO
   extraction in the existing error module. Permit missing-property fallback only
   for `MAPI_E_NOT_FOUND` (`0x8004010F`), directly or wrapped by `DISP_E_EXCEPTION`
   (`0x80020009`), with no conflicting status. Reject denied, invalid-entry, file,
   unknown or malformed error states. Keep general item lookup behavior unchanged.
2. A successful value must be a string: an empty string means no represented SMTP
   override; a nonempty string must validate as explicit SMTP. Reject `None` and
   other unexpected types. An existing real synthetic draft returned an empty string.
   Continue resolving any nonempty represented display name and requiring account
   equality. No error-message parsing or provider-specific fallback is introduced.
3. Prove direct and wrapped absence, signed HRESULTs, conflicting statuses,
   invalid EntryID/file errors, absent/nonempty represented names and unexpected
   successful types. Recheck a real existing draft preview without creation/send,
   then independently review the exact corrected candidate before publication.

Microsoft documents [property read errors and return types](https://learn.microsoft.com/en-us/office/vba/api/outlook.propertyaccessor.getproperty),
the [represented SMTP string type](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxprops/03690c3c-cdf9-48b8-ad2e-f4b681bbeb1b)
and distinct [MAPI error definitions](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxcdata/21bc846a-7c15-4b4b-98ec-b57df01bf03e).
Research is complete for this bounded rule. Reusing the broad locator category was
rejected; removing optional sending would leave the authorized journey incomplete.
No new infrastructure is needed. Independent challenge of this correction is pending;
the previous review/correction history remains applicable.

### Delivery sequence

1. Challenge this contract's permissions, account selection, revision continuity,
   mutation ambiguity and reuse before implementing. Resolve blocking findings.
2. Implement R1/R2/R3/R4 with strict models and COM protocols. Synthetic tests prove
   default absence of write tools, worker rejection, correct account/recipients,
   save-without-send and original-message preservation. Verify a synthetic draft
   through a real MCP client and open that draft in Outlook; retain no mail content
   in receipts. Any test drafts left in Outlook must be disclosed.
3. Implement R5/R6 using existing traversal. Test cross-store identity, pagination,
   unsupported conversations, all filter combinations and inaccessible metadata.
   Verify conversation/filter calls against Outlook without saving results.
4. Implement R7 and mutation error semantics. Tests prove stale/reused token rejection,
   exact preview fields, non-default accounts, default-disabled send and no automatic
   retry after a simulated send/worker failure. Verify a real draft preview. A live
   test transmission requires an explicitly authorized recipient; absent that,
   report sending as simulated and do not invent a sent-message receipt.
5. Run full checks, build, independently review the exact candidate, open a PR,
   integrate and publish a versioned release. Verify the public installation and
   update local clients deliberately. Preserve v0.1.0 installation paths.

Research: required because write/send/conversation behavior has external effects;
Microsoft Object Model references establish Display, Reply, Save, SendUsingAccount
and Conversation.GetTable. Challenge and independent implementation review are
required. This contract does not itself prove implemented behavior.

The independent challenge identified account ambiguity and represented From identity,
conservative dispatched-mutation recovery, recipient roles in the preview digest,
cross-store conversation rows and long quoted replies. The rules above incorporate
those findings. No additional service, persistence or coordination mechanism was needed.

The real draft/account probe invalidated the premise that SendUsingAccount survives
re-fetching. Independent re-challenge approved explicit preview account binding and
the before/after PUTREF validation sequence above. Two synthetic drafts were retained;
no live transmission occurred. The implementation must prove the revised journey.

## Efficient client use (additional owner request)

The observed client journey repeatedly copied long native IDs, discovered folders
before default Inbox searches, fetched excessive bodies and called COM tools in
parallel. Date searches also failed at the Windows formatter, independently of Outlook
availability. The formatter correction is verified through real Windows and MCP calls.

R8 (independent challenge approved): return short typed in-memory references
for native store/folder/item IDs and accept them on subsequent calls, retaining raw-ID
input compatibility. Translate IDs only at the worker JSON boundary; keep adapter and
cursor identities native. Use the existing ten-minute lifetime and bounded memory
budgets, explicit expiry/capacity errors, no silent eviction/rebinding and clear on
worker reset. Never cache mail content. Reduce default read body pages to 2,000
characters. Tool/server instructions guide sequential calls, direct default-Inbox
searches, normal 20-item pages and metadata-first answers. Expanding scope or body
reads requires a reason from the user's question. Measure synthetic response size and
verify a real date search followed by a short-reference read; test restart expiry.

Item/folder references and reverse keys include the native store identity; incoming
references must match the supplied store after expansion. Successful use or re-emission
refreshes reference lifetime without extending cursors or send tokens. Only declared
ID fields are translated. REFERENCE_LIMIT explicitly resets the backend's references,
cursors and previews, including unpublished tokens from a failed response. Post-mutation
output failures remain WRITE_OUTCOME_UNKNOWN. Unknown typed refs never fall back to
native IDs. Report measured JSON-byte savings, not unmeasured token counts.
